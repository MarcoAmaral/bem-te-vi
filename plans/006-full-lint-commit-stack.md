## Why this matters

`docs/specs/qa-skill-overhaul.md` §3 asks for eslint/prettier/lint-staged as devDependencies
plus a husky pre-commit hook, and §2 asks for husky + commitlint to enforce Conventional
Commits (already documented as required in `CONTRIBUTING.md` §2, but currently unenforced by
tooling — a contributor can still write a non-conventional commit message and nothing stops
them). The repo owner has explicitly confirmed they want the **full stack as specified**, even
though the repo is mostly Markdown/Bash with one JS file (`bin/cli.js`) — this is a deliberate
choice, not a scope mistake; do not scale it back.

## Steps

### Step 1: Install and configure ESLint + Prettier

Run `npm install --save-dev eslint prettier` (add exact versions to `package.json` as npm
resolves them — do not hand-pick version numbers). Create the ESLint config scoped to
`bin/cli.js`'s actual runtime (CommonJS, Node ≥16 per current `engines`, or whatever plan 008
bumped it to — check `package.json`'s `engines.node` at execution time and match ESLint's
`languageOptions.ecmaVersion`/`env` to it). Minimal flat config example (adjust for whichever
ESLint major you installed):

```js
// eslint.config.js
module.exports = [
  {
    files: ["bin/**/*.js"],
    languageOptions: {
      sourceType: "commonjs",
      ecmaVersion: 2022,
    },
    rules: {},
  },
];
```

Create `.prettierrc` (minimal, let Prettier's defaults apply — do not invent style rules not
already implied by the existing code):

```json
{}
```

Create `.prettierignore`:

```gitignore
adapters/
node_modules/
*.md
CHANGELOG.md
```

**Verify**: `npx eslint bin/cli.js` runs without crashing (report findings in NOTES, do not
auto-fix per "Out of scope" above). `npx prettier --check bin/cli.js` runs without crashing
(report pass/fail in NOTES, do not auto-fix).

### Step 2: Install and configure commitlint + husky

Run `npm install --save-dev husky @commitlint/cli @commitlint/config-conventional`.

Create `commitlint.config.js`:

```js
module.exports = { extends: ["@commitlint/config-conventional"] };
```

Run `npx husky init` (creates `.husky/` and adds a `"prepare": "husky"` script to
`package.json` automatically in recent husky versions — verify what it actually did with
`cat package.json` and `ls .husky/` rather than assuming; adjust the next steps if the
generated scaffold differs from what's described here).

Edit/create `.husky/commit-msg`:

```sh
npx --no -- commitlint --edit "$1"
```

Edit/create `.husky/pre-commit` (leave the lint-staged wiring for Step 3 — for now just ensure
the file exists and is executable; `husky init` may have already created a placeholder).

Make both hook files executable: `chmod +x .husky/commit-msg .husky/pre-commit`.

**Verify**: `echo "not a conventional commit" | npx commitlint` → exits non-zero (rejects).
`echo "chore: valid message" | npx commitlint` → exits 0 (accepts).

### Step 3: Install and configure lint-staged

Run `npm install --save-dev lint-staged`. Add to `package.json`:

```json
"lint-staged": {
  "*.js": ["eslint --fix", "prettier --write"]
}
```

(Only `*.js` — see "Out of scope": never add a `*.md` entry here.)

Set `.husky/pre-commit` to:

```sh
npx lint-staged
```

**Verify**: `npx lint-staged --dry-run` (or stage a trivial change to `bin/cli.js` and run
`npx lint-staged`) completes without error.
